# Soundscape --- Next Phase: Real Music Catalog & Spotify

## Status

Soundscape v2 is currently in a strong verified state:

-   Production build passes
-   TypeScript passes
-   Master E2E passes
-   Resilience tests pass
-   Provider coverage passes
-   Jamendo verification passes
-   Local FLAC coverage is reproducible
-   Repository is pushed and clean
-   Core playback works without Spotify

**Do not destabilize this baseline.**

The next phase is not another general cleanup. The product requirement
has changed: Soundscape must feel like a **real music streaming
application**, with recognizable artists, proper artist/album discovery,
and useful search.

# 1. Fix Spotify OAuth Redirect URI

## Problem

Spotify currently shows:

`redirect_uri: Not matching configuration`

The repository already has a BFF/PKCE Spotify authentication
architecture, so do not rewrite authentication blindly.

## Required investigation

Determine the **exact redirect URI generated at runtime** by the current
Soundscape implementation.

Inspect:

-   `server.ts`
-   `src/services/spotifyAuth.ts`
-   `src/config/redirectUri.ts`
-   environment/configuration
-   the actual authorize URL generated by the running application

Record the exact `redirect_uri` being sent to Spotify.

Then compare it with the redirect URI configured in the Spotify
Developer Dashboard.

## Required outcome

Make the development/local Spotify OAuth flow work with the exact
configured redirect URI.

The redirect URI must match exactly:

-   scheme
-   host
-   port
-   path
-   trailing slash behavior

Do not solve this by weakening security or accepting arbitrary redirect
URIs.

## Verification

After fixing:

1.  Open Soundscape.
2.  Start Spotify login.
3.  Confirm Spotify authorization page loads without the redirect URI
    error.
4.  Complete OAuth.
5.  Confirm Soundscape returns to the application.
6.  Confirm `/api/auth/status` reports an authenticated state.
7.  Confirm the browser receives no Spotify client secret.
8.  Confirm PKCE/state protections remain intact.
9.  Test logout and confirm the session returns to disconnected state.

If live Spotify credentials or Developer Dashboard configuration are
unavailable, clearly report exactly what remains unverified rather than
claiming success.

# 2. Diagnose the Current Search Architecture

## Problem

Searching for an artist currently does not behave like a real music
application.

Examples:

-   `The Weeknd`
-   `Nanku`

The user expects to find the actual artist and their songs.

The current open-catalog system primarily searches playable content
across:

-   Audius
-   Jamendo
-   Internet Archive

These sources are useful for legitimate open playback but are **not
equivalent to a commercial music catalog**.

## Required investigation

Map the current search pipeline end-to-end:

``` text
Search input
    ↓
SearchScreen
    ↓
provider queries
    ↓
result normalization
    ↓
deduplication
    ↓
UI result grouping
    ↓
artist/album/track interaction
    ↓
playback resolution
```

Identify exactly:

-   which providers receive the query
-   which providers support artist entities
-   which providers support albums
-   which providers support track search
-   how artist names are normalized
-   whether exact artist matching exists
-   whether artist pages exist
-   whether album pages exist
-   whether clicking an artist can retrieve its discography
-   why an artist query can return no useful results
-   what happens when Spotify is disconnected

Do not guess.

## Required product behavior

Search should support a Spotify-like discovery experience.

For a query such as:

`The Weeknd`

the UI should be able to show meaningful sections such as:

``` text
Artists
  The Weeknd

Albums
  Starboy
  After Hours
  Dawn FM
  ...

Tracks
  Blinding Lights
  Starboy
  Save Your Tears
  ...
```

For:

`Nanku`

the same architecture should work if the selected catalog provider
actually contains that artist/catalog.

## Important

Do not fabricate results.

Do not use AI-generated artists.

Do not invent album artwork.

Do not create fake tracks when a provider returns nothing.

Every displayed artist/album/track must originate from a real provider
response.

-   album artwork
-   album title

-   album discovery

The target experience includes recognizable artists such as:

# 7. Decide the Provider Architecture

The existing open providers should not be destroyed.

Keep:

``` text
Audius
Jamendo
Internet Archive
Radio Browser
Local files
Subsonic/Navidrome/Jellyfin
```

These are valuable for legitimate open/free/personal playback.

Add a proper commercial-catalog integration only if the provider's
current API terms and capabilities support it.

The architecture should become conceptually:

``` text
                 ┌──────────────────┐
                 │   Search Query    │
                 └────────┬─────────┘
                          │
        ┌─────────────────┼──────────────────┐
        ↓                 ↓                  ↓
 Commercial Catalog   Open Catalog      Personal Library
        │                 │                  │
   Spotify/etc.      Audius/Jamendo      Local/Subsonic
                     /Archive
        │                 │                  │
        └─────────────────┼──────────────────┘
                          ↓
                 Unified Search UI
                          ↓
                Artist / Album / Track
                          ↓
                  Real Playback
```

The provider capability system already exists. Extend it rather than
creating a second unrelated architecture.

------------------------------------------------------------------------

# 8. Spotify Must Remain Optional to the Core Player

Even if Spotify becomes the primary commercial discovery/playback
provider:

**Do not make Soundscape completely unusable without Spotify.**

The open catalog and local playback must continue working.

Spotify failure should result in an honest state such as:

``` text
Spotify isn't connected.
Connect Spotify to access your Spotify library and Spotify playback.
```

It must never silently replace Spotify tracks with unrelated random
tracks.

------------------------------------------------------------------------

# 9. Search Quality Requirements

Search should distinguish between:

### Artist query

Example:

``` text
The Weeknd
```

Prefer:

``` text
Artist: The Weeknd
```

rather than showing ten unrelated tracks that merely happen to contain
similar text.

### Track query

Example:

``` text
Blinding Lights
```

Prefer exact/near-exact track matches.

### Artist + track

Example:

``` text
The Weeknd Blinding Lights
```

Prefer exact artist + title matches.

### Indian artist queries

Examples:

``` text
Nanku
Karan Aujla
DIVINE
Seedhe Maut
```

Results should be based on actual provider metadata.

------------------------------------------------------------------------

# 10. Result Ranking

Create a deterministic ranking strategy.

Prefer:

1.  Exact artist match
2.  Exact track title + artist match
3.  Exact album match
4.  Strong normalized text match
5.  Provider confidence
6.  Playability
7.  Quality

Never rank a random playable track above an exact artist/entity match
simply because it happens to be playable.

------------------------------------------------------------------------

# 11. No Fake Fallbacks

This is a hard requirement.

If:

``` text
Search: The Weeknd
```

Instead:

``` text

```

or:


depending on the actual provider state.

``` text

        ↓
The Weeknd — Artist
        ↓
Artist page
        ↓
Albums / tracks
        ↓
Select song
        ↓
Real provider playback
        ↓
Real metadata + artwork
```

while still supporting:

``` text
Audius
Jamendo
Internet Archive
Radio
Local files
Subsonic/Navidrome/Jellyfin
```

with honest provider attribution and failure states.

**The objective is not to make Soundscape look like Spotify.**

The objective is to make its catalog/search/playback behavior feel like
a real music application while remaining technically and legally
legitimate.
